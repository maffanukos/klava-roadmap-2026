# Prompt для ИИ: ТЗ #6 (мультиаккаунт как в Telegram)

Ты senior engineer в проекте `element-web`.  
Нужно реализовать мультиаккаунт с переключением в user menu.

## Зафиксированные требования

1. Неограниченное количество аккаунтов.
2. Переключение с мягкой перезагрузкой UI (soft reload), без повторного логина.
3. В карточке неактивного аккаунта показывать:
   - общий unread;
   - важные/mentions отдельно.
4. После рестарта восстанавливать все аккаунты и порядок.
5. Без re-auth при обычном переключении.
6. Локация: меню профиля (user menu).
7. Действия: switch, mute, logout single account, reorder.

## Технический контур

- Ввести слой AccountRegistry + ActiveAccountStore.
- Реализовать switch orchestrator с состояниями `idle/switching/failed`.
- Обеспечить изоляцию данных аккаунтов.
- Реализовать unread aggregation в фоне по неактивным аккаунтам.

## Ограничения

- Не ломать существующие single-account сценарии.
- Не делать нерелевантный глобальный рефакторинг.
- Изменения должны быть модульными и ревьюопригодными.

## Формат результата

1. Архитектурная схема (кратко).
2. Список измененных файлов.
3. Что сделано по каждому блоку:
   - data model
   - switching runtime
   - user menu UI
   - unread counters
   - security/session
4. Риски и компромиссы.
5. Checklist ручной проверки + список автотестов.
