# Проблема №2: центр встреч (Запланированные / История) + мастер создания/планирования

## Цель

Сделать в Клаве понятный и управляемый раздел встреч по паттерну Index5:

- вкладки `Запланированные` и `История встреч`;
- быстрые действия `Начать встречу` и `Запланировать встречу`;
- единое модальное окно (мастер) для создания/редактирования встречи;
- карточки встреч с нужными действиями (запуск, копия ссылки, настройки, удаление);
- явная модель участников встречи (`в звонке / не в звонке`) для экрана конференции.

## Что именно реализуем (scope)

### 1) Новый экран/раздел «Мои встречи»

- Вкладка по умолчанию: `Запланированные`:
  - показывает встречи в будущем;
  - показывает встречи, идущие прямо сейчас.
- Вкладка `История встреч`:
  - дата/время прошедшей встречи;
  - название;
  - действие «проиграть запись»;
  - действие «посмотреть конспект» (иконка файла).

### 2) Верхние кнопки

- `Начать встречу`:
  - открывает модалку создания;
  - поля: название, участники, тип встречи, переключатель `Комната ожидания` (по умолчанию `off`);
  - создаёт и сразу запускает встречу.
- `Запланировать встречу`:
  - открывает ту же модалку + дата/время старта;
  - создаёт запись во вкладке `Запланированные`.

### 3) Типы встречи (пресеты)

- HR-собеседование
- Встреча с клиентом
- Командное совещание
- Инкогнито
- Обучение

Для каждого пресета задаём набор дефолтов (флаги/политики/шаблоны), которые можно редактировать в модалке.

### 4) Действия в строке запланированной встречи

- Запустить встречу
- Копировать ссылку:
  - для сотрудника;
  - для внешнего пользователя
- Настроить встречу (модалка в режиме edit с заполненными полями)
- Удалить встречу

### 5) Пояснение про правую панель участников (из проблемы №2)

- В интерфейсе конференции добавляем фильтры/табы:
  - `Все`
  - `В звонке`
  - `Не в звонке`
- Для каждого участника показываем явный статус присутствия.

## Функциональная декомпозиция (US -> задачи)

## Epic A. Центр встреч

### US A1. Вкладки `Запланированные` / `История`

**Frontend**

- Сделать layout экрана «Мои встречи» с 2 табами и поиском.
- Реализовать правила выборки:
  - `Запланированные`: now/future + active now;
  - `История`: ended.
- Пагинация/ленивая подгрузка.

**Backend**

- API списка встреч с фильтром `planned|history|active`.
- Нормализация статусов встречи (`scheduled`, `active`, `ended`, `cancelled`).

**QA**

- Проверка граничных дат/таймзон.
- Проверка сортировки и консистентности вкладок.

---

### US A2. Карточка/строка встречи в списке

**Frontend**

- Колонки: дата/время, название, действия.
- Для `История`: кнопки `play record`, `open summary`.
- Для `Запланированные`: `start`, `copy link`, `settings`, `delete`.

**Backend**

- Эндпоинты: `start`, `delete`, `get recording`, `get summary`, `get links`.

**QA**

- Проверка прав доступа к действиям.
- Проверка обработки ошибок (нет записи, нет конспекта и т.д.).

---

### US A3. Копирование двух типов ссылок

**Frontend**

- Меню выбора: `Ссылка для сотрудника` / `Ссылка для внешнего`.
- UX-фидбек «ссылка скопирована».

**Backend**

- Генерация двух типов invite-link с разными политиками доступа.

**QA**

- Валидация, что ссылки действительно ведут в корректные режимы.

---

## Epic B. Мастер создания/планирования встречи

### US B1. Единая модалка create/edit

**Frontend**

- Модалка в режимах:
  - `createInstant` (Начать встречу);
  - `createScheduled` (Запланировать);
  - `editScheduled` (Настроить).
- Поля: название, участники, тип встречи, ожидание, дата/время (только для schedule/edit).

**Backend**

- DTO встречи (единый контракт create/update).
- API create/update/read.

**QA**

- Проверка валидаторов формы.
- Проверка пресетов и ручных переопределений.

---

### US B2. Пресеты типов встречи

**Frontend**

- UI выбора пресета.
- Отображение/подсказки включённых политик.

**Backend**

- Справочник пресетов и их дефолтные policy-флаги:
  - шифрование;
  - разрешение записи;
  - гостевой режим;
  - авто-приглашение;
  - шаблон заметок и т.д.

**QA**

- Проверка, что пресет применяет дефолты корректно.
- Проверка изменения дефолтов вручную.

---

## Epic C. Экран активной конференции (понятность участников)

### US C1. Фильтры участников

**Frontend**

- Табы/фильтры: `Все / В звонке / Не в звонке`.
- Явные статусные бейджи участника.

**Backend**

- (Опционально) endpoint membership/presence snapshot, если текущих данных Matrix недостаточно.

**QA**

- Сверка статусов при join/leave в реальном времени.

---

## Epic D. Интеграции и спецрежимы (внутри пресетов)

### US D1. Политики пресетов

- HR: шифрование, запись off, автоссылка кандидату, шаблон заметок.
- Клиент: гостевой режим, бренд-комната, автоматериалы.
- Командное: календарь, автоподключение отдела, запись + транскрипт.
- Инкогнито: E2EE, одноразовая ссылка, автоудаление истории.
- Обучение: «только спикер», квизы, автоотчет.

> Рекомендуется вводить по фазам: сначала UI+контракты, затем фактические интеграции.

## Риски и зависимости

- Нужна синхронизация с текущей архитектурой module runtime (часть меню и поведения может жить вне этого репо).
- Для «записи/конспекта/транскрипта/автоотчётов» требуются отдельные backend-сервисы и хранение артефактов.
- Внешние пользователи и «инкогнито» требуют чёткой security-модели (access scope, TTL, revoke).
- Точное время зависит от готовности API календаря/оргструктуры/identity.

## Критерии приёмки (минимум)

- Пользователь понимает:
  - где запланированные, где история;
  - как быстро создать/запланировать/запустить встречу;
  - кто реально в звонке, а кто только в комнате.
- Действия в строке встречи отрабатывают без переходов в «тупик».
- Внутренние и внешние ссылки корректно разделены.
