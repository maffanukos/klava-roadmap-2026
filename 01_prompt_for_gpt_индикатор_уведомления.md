# Инструкция для GPT (Проблема №1)

Ты senior product+tech analyst. Нужно подготовить implementation spec по проблеме:
"В Клаве есть уведомление о конференции/звонке, но неясно, к чему оно относится. Нужен явный индикатор источника."

Контекст:
- UI модулей слева: `Мессенджер`, `Конференции`, `Справочник`, `Звонки`.
- Уведомления звонков уже есть (`CallNotificationService`, `SelectiveCallToast`), но нет надежной привязки к конкретному модулю в навигации.
- Модульные пункты задаются через runtime modules (`SdkConfig.modules`, `ModuleLoader`, `setSpacePanelItem`).

Сделай результат в структуре:

1) Коротко: root cause (3-5 пунктов).
2) Target UX:
   - как выглядит индикатор;
   - куда ведет клик;
   - как отображается контекст (кто/где/тип события).
3) Техдизайн:
   - контракт payload (json schema);
   - mapping `event -> moduleKey -> deep-link`;
   - state machine индикатора (`idle`, `unread`, `active`, `dismissed`).
4) Plan работ:
   - Frontend / Backend / QA / Design;
   - декомпозиция на задачи уровня US -> task;
   - зависимости и риски.
5) Оценка в часах:
   - MVP, Full, AI, No-AI;
   - отдельно по ролям (FE/BE/QA/Design);
   - total и допущения.
6) Критерии приемки:
   - функциональные;
   - UX;
   - регрессия.
7) Rollout strategy:
   - feature flag;
   - метрики успеха;
   - план отката.

Ограничения:
- Пиши на русском.
- Формат: четко, без воды, таблицы где нужно.
- Не придумывай абстракции без практического применения.
- Если чего-то не хватает, явно перечисли assumptions.
