# Проблема №7: личные статусы (создание, редактирование, срок действия)

## Цель

Дать пользователю удобный инструмент управления личным статусом прямо из меню профиля:

- создать статус;
- редактировать статус;
- задавать срок действия;
- сбрасывать статус;
- показывать активный статус в шапке пользователя и в профиле для других.

---

## Что уже сделано в прототипе

- В `UserMenu` добавлен UI-блок статуса:
  - создание/редактирование;
  - выбор эмодзи;
  - текст статуса (ограничение до 100 символов);
  - выбор срока: `1 час`, `до конца дня`, `7 дней`, `Показывать всегда`, `точная дата и время`;
  - сброс статуса по `×`;
  - список шаблонов/сохраненных статусов (UI).
- В шапке левой панели (`mx_UserMenu`) статус отображается под именем.
- В `UserInfo` добавлено отображение статус-сообщения пользователя.
- Добавлена компактная верстка контекстного меню, чтобы блоки не растягивали экран.

---

## Scope

### S1. Управление статусом

- Эмодзи: любой символ/эмодзи.
- Описание: до 100 символов (с пробелами).
- Срок действия:
  - предустановки;
  - точная дата и время;
  - режим “Показывать всегда”.

### S2. Отображение

- В меню пользователя: текущий статус + управление.
- В шапке левой панели: компактный активный статус.
- В профиле пользователя (`UserInfo`): отображение статуса для других.

### S3. Жизненный цикл статуса

- Создание.
- Редактирование (эмодзи, текст, срок).
- Сброс/удаление.
- Автоистечение по времени (next step).

## Инструкции разработчикам (человеческие)

### Задача A (управление статусом)

1. Оставить весь контроль в рамках `UserMenu`, без открытия отдельного тяжелого окна.
2. Лимит 100 символов валидировать на вводе, не только на submit.
3. Для custom datetime проверять валидность и timezone пользователя.

### Задача B (верстка)

1. Держать `UserMenu` фиксированной ширины.
2. Ограничить высоту и сделать контролируемую внутреннюю прокрутку.
3. Сохранить визуальную консистентность с темой приложения.

### Задача C (отображение)

1. Статус в шапке — короткий, второстепенный по визуальному весу.
2. В `UserInfo` статус должен быть читаем, но не ломать header.

### Задача D (данные)

1. Сначала поддержать надежное локальное состояние.
2. Затем добавить публикацию в сеть (presence/account data) с fallback-веткой.
3. Не блокировать UI при ошибках синхронизации.

## Тест-кейсы для QA

## F1. Создание/редактирование статуса

### TC-F1-01 Создание статуса

- Шаги: задать эмодзи, текст, срок и сохранить.
- ОР: статус отображается как активный.

### TC-F1-02 Лимит текста

- Шаги: ввести >100 символов.
- ОР: текст ограничен 100 символами.

### TC-F1-03 Редактирование

- Шаги: поменять эмодзи, текст и срок.
- ОР: отображается обновленный статус.

### TC-F1-04 Сброс

- Шаги: нажать `×` или `Сбросить`.
- ОР: активный статус очищен.

## F2. Срок действия

### TC-F2-01 Пресеты

- Шаги: выбрать `1 час`, `до конца дня`, `7 дней`, `всегда`.
- ОР: метка срока отображается корректно.

### TC-F2-02 Точная дата/время

- Шаги: выбрать custom datetime.
- ОР: срок сохраняется и корректно отображается.

### TC-F2-03 Автоистечение (после реализации D3)

- Шаги: дождаться времени истечения.
- ОР: статус сбрасывается автоматически.

## F3. Отображение

### TC-F3-01 Шапка пользователя

- Шаги: установить статус и проверить левую панель.
- ОР: статус виден под именем.

### TC-F3-02 Профиль пользователя

- Шаги: открыть `UserInfo`.
- ОР: статус виден в header профиля.

### TC-F3-03 Другой пользователь

- Шаги: открыть профиль этого пользователя из другой учетки.
- ОР: статус виден (при поддержке backend/федерации).

## F4. Верстка

### TC-F4-01 Высота меню

- Шаги: открыть user menu на экранах 768/900/1080 по высоте.
- ОР: меню не растягивается на весь экран, контент прокручивается локально.

### TC-F4-02 Консистентность состояния

- Шаги: hover/focus/active по контролам статуса.
- ОР: визуальные состояния корректны.
