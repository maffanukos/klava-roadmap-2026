# Проблема №9: Доски (аналог Miro)

## Бизнес-цель

Дать командам единое пространство для совместной визуальной работы (брейнштормы, планирование, ретро, проектирование), чтобы снизить фрагментацию инструментов и ускорить принятие решений.

---

## Продуктовая цель

Добавить в Клаву модуль `Доски`:

- отдельный раздел в левом меню между `Задачи` и `Контакты`;
- создание и поиск досок;
- работа с контентом доски через набор виджетов;
- совместная работа и шаринг;
- гибкие права доступа.

---

## Scope (One-release: MVP + Full в одном цикле)

### S1. Навигация и сущность доски (MVP)
- Пункт `Доски` в левом меню.
- Экран списка досок: поиск по названию, создание доски, дублирование.
- Карточка доски: title, owner, project/folder, updatedAt.

### S2. Базовый редактор (MVP)
- Бесконечное полотно.
- Навигация мышь/тачпад, zoom/pan.
- Виджеты MVP: стикер, текст, стрелка, фигура/диаграмма, рисунок, фрейм, изображение, таблица, карточка.

### S3. Совместная работа и доступы (MVP)
- Мультиплеер на доске (presence/cursors).
- Шаринг доски.
- Роли доступа: `owner`, `editor`, `commenter`, `viewer`.
- Опционально пароль на доску.

### S4. Расширенные функции (в этом же релизе)
- Шаблоны, майндмап, реакции, голосования, комментарии (thread/resolve), iFrame.
- Импорт из Miro.
- PDF с пагинацией/пином страницы.
- Аудит-логи (для owner/admin, включаемая опция).
- Интеграция с ВКС (создать/подключить доску во встрече).

---

## Зафиксированные решения по ТЗ 9

1. Раздел `Доски` добавляется в левое меню **между** `Задачи` и `Контакты`.
2. Архитектура: клиент в веб-браузере, сервер обрабатывает запросы с учетом прав участника Организации.
3. Формат поставки: **one-release**, пользователь запросил весь контур в одном релизе.
4. Допускается **гибридная реализация**: временные `stub`-слои разрешены только как переходный этап в этом же цикле с сохранением контрактов под backend.
5. В досках поддерживается переключаемый режим data-layer `stub/real` без изменения UI-контрактов.
6. Основной deep-link для раздела: `#/boards`, deep-link на конкретную доску: `#/boards?board=B-xxxx`.
7. Основной UX списка и канваса дорабатывается итеративно по визуальному референсу конкурентов.

## Что реализовано сейчас (факт на сегодня)

### 1) Навигация и вход
- В левом меню добавлен пункт `Доски` между `Задачи` и `Контакты`.
- Добавлены маршруты и действия:
  - `CustomSpace.Boards`,
  - `Action.OpenBoards`,
  - `PageType.BoardsView`,
  - переходы по `#/boards` и `#/boards?board=B-xxxx`.

### 2) Data-layer и контракты
- Введены типы: `BoardSummary`, `BoardDetail`, `BoardMember`, `BoardRole`, `BoardWidget`, `CommentThread`, `VoteSession`, `AuditEvent`, `ImportJob`.
- Введен API-контур:
  - `BoardsApi` (единый интерфейс),
  - `StubBoardsApi`,
  - `RealBoardsApi` (текущий pass-through к stub с сохранением prod-контракта),
  - `boardsGateway` для переключения режима `stub/real`.
- Реализован ACL-резолвер по ролям `owner/editor/commenter/viewer`.

### 3) Главный экран Досок
- Реализован обновленный UX:
  - внутренний сайдбар (разделы и проекты),
  - большая строка поиска,
  - ряд быстрых шаблонов,
  - плиточная сетка карточек досок,
  - отдельная плитка `Создать доску`.
- Реализованы фильтры:
  - по роли доступа,
  - по проекту,
  - по владельцу.
- Реализовано создание доски через модалку и открытие карточки доски.

### 4) Canvas (рабочий контур)
- Реализован `BoardCanvasView`:
  - бесконечное полотно,
  - pan/zoom,
  - undo/redo,
  - drag виджетов.
- Реализованы инструменты:
  - навигация, стикер, диаграмма, стрелка, текст, рисунок, фрейм, реакция, изображение, таблица, карточка, шаблон, майндмап, PDF, iFrame.
- Реализован редизайн панели инструментов в сторону Miro-подобного вида (иконка + подпись).

### 5) Совместная работа, доступы, enterprise-функции
- Realtime-контур (BroadcastChannel):
  - presence (участники онлайн),
  - синхронизация изменений виджетов между вкладками.
- Реализован шаринг с назначением ролей участников.
- Реализованы комментарии (создание, resolve/open), режим голосований (start/finish).
- Реализованы кликабельные ссылки внутри виджетов.
- Реализована загрузка image/PDF как виджетов.
- Реализован процесс импорта Miro:
  - старт job,
  - polling статуса,
  - фиксация `import_miro_started/import_miro_finished`.
- Реализованы флаги интеграций:
  - ВКС,
  - SSO,
  - audit logs.
- Реализованы аудит-логи с фильтром по датам.

### 6) Технические нюансы/ограничения текущей версии
- `RealBoardsApi` пока работает как мост через `StubBoardsApi`; реальный HTTP/backend слой требует отдельного подключения endpoint-ов.
- Realtime сейчас на `BroadcastChannel` (в пределах браузера/вкладок), а не на серверном websocket-канале.
- Импорт Miro пока в формате локального job-пайплайна (мок-сценарий прогресса), без реального маппинга Miro JSON.
- При попытке использовать часть внешних SVG-mask иконок был получен критичный сбой UI с `Unknown theme light`; иконки переведены на безопасный вариант (символьные), требуется отдельная controlled-интеграция полного икон-пака.

- B3. Search API по названию.
- B4. Permission-check middleware.
- B5. Реальный HTTP-клиент для `RealBoardsApi` + DTO mapping + auth headers.

- C1. Координатная система и бесконечный canvas.
- C2. Модель виджетов и редактирование.
- C3. Undo/redo и batching операций.
- C4. Оптимизация производительности на больших досках.

## Epic D. Collaboration
- D1. Realtime-синхронизация изменений.
- D2. Presence/cursors.
- D3. Conflict resolution.
- D4. Режимы доступа editor/commenter/viewer.
- D5. Переход с BroadcastChannel на server realtime (ws/sse) с гарантией консистентности между пользователями.

## Epic E. Enterprise-функции
- E1. Проекты/папки.
- E2. Импорт Miro.
- E3. Аудит-логи.
- E4. Интеграция с ВКС и SSO.

## QA сценарии (минимум)

- Q1: пункт `Доски` открывает нужный экран и корректно подсвечивается в левом меню.
- Q2: переход по `#/boards` открывает раздел `Доски`.
- Q3: создание доски из UI создает запись и показывает ее в списке.
- Q4: поиск по названию возвращает релевантные доски.
- Q5: проверка ролей доступа (`owner/editor/commenter/viewer`) на чтение/редактирование.
- Q6: совместное редактирование одной доски двумя пользователями без потери данных.
- Q7: переход по `#/boards?board=B-xxxx` открывает нужную доску.
- Q8: режимы `API Stub/Real` не ломают UI-контракт списка/канваса.
- Q9: загрузка image/PDF создает виджеты с корректными метаданными.
- Q10: аудит-лог фиксирует `board_shared`, `widget_updated`, `vote_started`, `import_miro_*`.
- Q11: регресс темы: приложение не уходит в `ErrorView` при смене/рендере панели инструментов доски.
