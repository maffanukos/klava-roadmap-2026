# Prompt для ИИ: ТЗ #9 (Доски, аналог Miro)

Ты senior product engineer в проекте `element-web`.

## Цель

Реализовать модуль `Доски` с возможностью:

1. создавать новые доски;
2. работать на бесконечном полотне через виджеты;
3. делиться досками;
4. настраивать уровни доступа участников.

## Контекст UI

Уже сделан расширенный контур:
- пункт `Доски` в левом меню между `Задачи` и `Контакты`;
- `CustomSpace.Boards` + `Action.OpenBoards` + `PageType.BoardsView`;
- deep-link `#/boards` и `#/boards?board=B-xxxx`;
- главный экран досок с сайдбаром, поиском, шаблонами и карточками;
- рабочий `BoardCanvasView` с инструментами, undo/redo, comments/votes, import-status и audit view.

## Обязательные требования (one-release)

- Роутинг и навигация:
  - `CustomSpace.Boards`;
  - `Action.OpenBoards`;
  - `PageType.BoardsView`;
  - deep-link `#/boards`;
  - deep-link доски `#/boards?board=B-xxxx`.
- Список досок:
  - создание;
  - поиск по названию;
  - фильтры по роли/проекту/владельцу;
  - дублирование.
- Canvas:
  - бесконечное полотно;
  - zoom/pan;
  - undo/redo;
  - drag/drop перемещение;
  - инструменты: стикеры, текст, диаграммы/фигуры, стрелки, рисунки, фреймы, реакции, изображения, таблицы, карточки, шаблоны, майндмап, PDF, iFrame.
- Совместная работа:
  - мультиплеер;
  - presence/cursors.
- Доступы:
  - роли `owner`, `editor`, `commenter`, `viewer`;
  - серверная проверка прав для всех операций.
- Комментарии и голосования:
  - создание/resolve комментариев;
  - старт/завершение голосований.
- Импорт/вложения:
  - загрузка image/PDF как виджетов;
  - запуск/polling импорта Miro.
- Аудит:
  - запись и просмотр событий;
  - фильтр по датам.

## Реализация по слоям (обязательно)

1. `types/contracts` (`BoardSummary`, `BoardDetail`, `BoardWidget`, `CommentThread`, `VoteSession`, `AuditEvent`, `ImportJob`).
2. `BoardsApi` интерфейс + `StubBoardsApi` + `RealBoardsApi`.
3. `boardsGateway` с runtime-switch `stub/real`.
4. ACL-слой (`resolveBoardAcl`) и применение ограничений в UI.
5. UI-слой (`BoardsView`, `BoardCanvasView`) без ломки текущего роутинга.

## Ограничения

- Не ломать существующие разделы (`Сообщения`, `ВКС`, `Задачи`, `Контакты`).
- Реализацию вести слоями: `data model -> API -> realtime sync -> UI`.
- Для тяжелых сценариев использовать пагинацию/виртуализацию и батчинг операций.
- Учитывать, что текущий `RealBoardsApi` может быть временно pass-through к stub, но публичные контракты менять нельзя.
- Не использовать нестабильные икон-пути, которые могут привести к падению темы (`Unknown theme light`); икон-пак подключать только через проверенные ассеты.

## Формат результата

1. Список измененных файлов.
2. DTO/API контракты для досок, участников и виджетов.
3. Как реализованы права доступа.
4. Как реализована совместная работа (realtime/presence).
5. Что сделано по comments/votes/import/audit/integrations.
6. Ограничения и риски.
7. QA checklist (включая deep-link и тему).
