# План работ: ВКС-центр, русификация и модалка планирования (прототип)

## Контекст

По этому ТЗ уже собран рабочий UI-прототип в локальной среде `element-web`: обновлен раздел `ВКС`, модалка создания/планирования встречи, русификация ключевых элементов и структура левого меню.

Документ фиксирует:

- что уже реализовано;
- декомпозицию на задачи для продуктовой доводки;
- подробные инструкции разработчикам (человеческие);
- инструкции для ИИ по каждой задаче;
- тест-кейсы для QA по каждой фиче.

## 2) Декомпозиция на продуктовые задачи (next steps)

## Epic A. Product hardening для текущего прототипа

### A1. Финализация UX модалки (адаптивы, высоты, плотность)

**Результат:** модалка стабильно помещается на основных разрешениях без лишних скроллов.

### A2. Доводка доступности (a11y)

**Результат:** корректные aria-label, фокус-трап, порядок tab-навигации, контраст и кликабельность.

### A3. i18n-стандартизация

**Результат:** убрать “жесткие строки” в коде и перевести в словари локализации (ru/en), сохранив текущий русский UX.

## Epic B. Пользователи и участники

### B1. Устойчивый источник участников

**Результат:** получение и фильтрация участников из надежного источника (directory/room/org users), а не только из in-memory списка.

### B2. Модель ролей и статусов участника

**Результат:** единый формат отображения “в звонке / не в звонке / приглашен / отклонил”.

## Epic C. Календарная занятость

### C1. Контракт занятости (backend + frontend DTO)

**Результат:** вместо mock-графика использовать реальные данные `busy/free` через API.

### C2. UI/UX занятости v2

**Результат:** интерактивный слот-пикер, легенда, таймзоны, коллизии и подсветка лучшего окна.

## 3) Подробные инструкции разработчикам (человеческие)

### Задача A1. Финализация UX модалки

1. Зафиксировать целевые брейкпоинты: `1366x768`, `1536x864`, `1920x1080`.
2. Для режимов `Начать` и `Запланировать` использовать разные preset-размеры модалки.
3. Запретить скролл body под модалкой и оставить scroll только как fallback.
4. Сверить вертикальные ритмы: заголовок, поля, блок занятости, кнопки.
5. Для режима “Запланировать” оставить 2-колоночный layout: слева форма, справа занятость.
6. Провести визуальный smoke-check в темной теме.

### Задача A2. Доступность

1. Проверить `aria-label` у интерактивных элементов (чипы, кнопки удаления, подсказки).
2. Проверить порядок фокуса: сверху вниз, слева направо.
3. Проверить ESC/клик-вне-модалки/кнопку закрытия.
4. Проверить, что фокус возвращается на исходную кнопку (`Начать`/`Запланировать`).
5. Проверить контраст и `hover/focus` состояния.

### Задача A3. i18n-стандартизация

1. Собрать все русские строки, добавленные в прототип.
2. Вынести строки в translation keys.
3. Для ru оставить текущие формулировки, для en добавить базовые переводы.
4. Пройтись по компонентам ВКС, Threads/Settings/Support.
5. Прогнать snapshot/regression для ru/en.

### Задача B1. Устойчивый источник участников

1. Уточнить источник данных: user directory, org directory, участники комнат.
2. Реализовать нормализованный адаптер пользователя: `id`, `displayName`, `avatar`, `presence`.
3. Добавить debounce для поиска.
4. Добавить fallback при ошибке directory API.
5. Реализовать дедупликацию результатов.

### Задача B2. Роли и статусы

1. Утвердить набор статусов: `in_call`, `not_in_call`, `invited`, `declined`.
2. Привязать статус к визуальному бейджу и цветовой схеме.
3. Обновить строки списка участников и фильтры.
4. Добавить обработку realtime-обновлений (join/leave).

### Задача C1. Контракт занятости

1. Определить API контракт занятости:
  - вход: список пользователей, дата, диапазон времени, таймзона;
  - выход: набор слотов `busy/free/tentative`.
2. Реализовать адаптер на фронте и замену mock-логики.
3. Добавить fallback: если API не отвечает, показывать “данные недоступны”.
4. Логировать таймауты и ошибки.

### Задача C2. UI занятости v2

1. Добавить легенду цветов и подписи.
2. Добавить подсветку выбранного времени.
3. Добавить “лучшее окно” (наибольшее число свободных участников).
4. Добавить явную отметку таймзоны.
5. Добавить ограничение видимого списка участников + “показать еще”.

### TC-F2-01 Порядок пунктов

- Шаги: проверить последовательность в меню.
- ОР: `Сообщения -> ВКС -> Контакты`.

### TC-F2-02 Разделитель и заголовок комнат

- Шаги: проконтролировать блок между мета-пунктами и списком комнат.
- ОР: есть разделитель и заголовок `Комнаты`.

## F3. Центр встреч

### TC-F3-01 Вкладки

- Шаги: открыть `ВКС`, переключить вкладки.
- ОР: доступны `Запланированные` и `История встреч`, переключение корректно.

### TC-F3-02 CTA кнопки

- Шаги: проверить кнопки верхней панели.
- ОР: есть `Начать встречу` и `Запланировать встречу`, лишние кнопки отсутствуют.

## F4. Модалка overlay

### TC-F4-01 Поведение overlay

- Шаги: открыть модалку.
- ОР: модалка поверх интерфейса, фон затемнен/размыт, layout не сдвигается.

### TC-F4-02 Закрытие

- Шаги: закрыть через `X`, `Esc`, клик по фону.
- ОР: модалка закрывается во всех случаях.

### TC-F4-03 Скролл

- Шаги: проверить модалку на целевых разрешениях.
- ОР: нет лишней вертикальной прокрутки внутри модалки в типовом сценарии.

## F5. Участники из Клавы

### TC-F5-01 Поиск и подсказки

- Шаги: начать ввод в поле участников.
- ОР: появляются подсказки пользователей из Клавы.

### TC-F5-02 Добавление/удаление участников

- Шаги: добавить 2-3 участников, удалить одного.
- ОР: чипы обновляются корректно, дубликаты не добавляются.

### TC-F5-03 Сохранение

- Шаги: создать/запланировать встречу с выбранными участниками.
- ОР: в сохраненной сущности присутствуют выбранные userId.

## F6. Занятость (mock)

### TC-F6-01 Отображение диаграммы

- Предусловие: режим `Запланировать встречу`.
- Шаги: выбрать участников.
- ОР: справа видна диаграмма по пользователям и времени.

### TC-F6-02 Цветовая семантика

- Шаги: проверить слоты.
- ОР: занятость красная, свободные слоты синие.

### TC-F6-03 Empty state

- Шаги: открыть модалку без выбранных участников.
- ОР: отображается подсказка “Выберите участников...”.

### TC-F6-04 Ограничение отображения

- Шаги: выбрать >4 участников.
- ОР: диаграмма показывает ограниченный список + подпись `+N участн. не показано`.
