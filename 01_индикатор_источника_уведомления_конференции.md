# Проблема №1: индикатор источника уведомления о конференции

## Симптом
- В шапке/навигации появляется сигнал о звонке или конференции.
- Пользователю не очевидно, к какому модулю относится событие (`Конференции`, `Звонки` или конкретная комната).

## Что подтверждено в коде
- Уведомления о звонках формируются в `CallNotificationService` и показываются через `SelectiveCallToast`:
  - `d:\Klava web\element-web\src\utils\call\CallNotificationService.ts`
  - `d:\Klava web\element-web\src\toasts\SelectiveCallToast.tsx`
- Бейджи в левом меню рендерятся через `SpaceButton -> NotificationBadge`:
  - `d:\Klava web\element-web\src\components\views\spaces\SpaceTreeLevel.tsx`
- Модульные пункты меню подмешиваются через Runtime modules (plugin API):
  - `d:\Klava web\element-web\src\modules\ExtrasApi.ts`
  - `d:\Klava web\element-web\src\vector\init.tsx` (`SdkConfig.get("modules")`, `ModuleLoader`)

## Ключевой вывод по источнику проблемы
- Источник данных уведомления (звонок/конференция) и источник UI-подсветки (модульный пункт слева) сейчас слабо связаны.
- Критичная часть настройки модульных пунктов (`setSpacePanelItem`) находится во внешнем runtime-модуле (или конфиге с `modules`), а не в этом репозитории.
- Из-за этого пользователь видит событие, но не получает однозначный визуальный ответ "где это".

## Решение (рекомендуемый вариант)
1. Ввести единый payload уведомления звонков/конференций с обязательными полями маршрутизации.
2. Завести адаптер `NotificationToModuleMapper`, который по payload определяет целевой модуль (`conferences`, `calls`, `messenger`).
3. Прокинуть `notificationState`/badge в `SpacePanelItem` для целевого модуля.
4. По клику по индикатору выполнять deep-link в конкретный экран/комнату.
5. Добавить "source chip" в toast (например, `Конференции · Win Solutions`) для мгновенного контекста.

## Контракт payload (предлагаемый)
```json
{
  "eventId": "uuid",
  "type": "conference.invite | conference.active | conference.missed | call.incoming | call.missed | call.ended",
  "target": {
    "moduleKey": "conferences | calls | messenger",
    "roomId": "!room:server",
    "spaceKey": "custom-space-key"
  },
  "participants": {
    "callerUserId": "@user:server",
    "callerDisplayName": "Иван Иванов"
  },
  "meta": {
    "roomName": "Проект AVA",
    "startedAt": 1714570000000,
    "priority": "high | normal",
    "ttlMs": 90000
  },
  "actions": {
    "openUrl": "#/room/!room:server",
    "acceptAction": "join",
    "dismissAction": "dismiss"
  }
}
```

## Декомпозиция по потокам

### Frontend
- Добавить mapper `event -> moduleKey/roomId/deeplink`.
- Привязать badge к модульным пунктам (`SpacePanelItem.notificationState`).
- Обновить toast: показать контекст источника + прямой переход.
- Сценарии edge-cases: два события одновременно, событие устарело, мульти-девайс dismiss.

### Backend (или сервис событий)
- Расширить payload полями `moduleKey`, `roomId`, `roomName`, `callerDisplayName`, `priority`.
- Стабилизировать event type enum.

### QA
- E2E матрица: входящий/пропущенный/завершенный, параллельные звонки, переключение модулей, синхронизация между устройствами.

### Design
- Спека badge и тултипа в модульной навигации.
- Состояния: unread, active conference, dismissed.

## Оценка часов (переоформлено)

### Важно про трактовку "с ИИ"
- Здесь "AI-first" означает: ИИ реализует большую часть кода, человек делает постановку, ревью, интеграционный контроль и приемку.
- Это **не** добавление AI-функций в продукт.

## Зависимости и риски
- Нужен доступ к runtime-модулю, где фактически вызывается `setSpacePanelItem(...)`.
- Если payload звонков формируется несколькими сервисами, потребуется унификация схемы событий.
- Возможна корректировка часов после просмотра внешнего модуля меню (обычно +/- 15%).
