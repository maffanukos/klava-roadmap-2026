# Инструкция для GPT (Проблема №2)

Ты senior product+tech analyst. Нужно подготовить implementation spec для фичи:
"Центр встреч в стиле Index5: Запланированные/История, мастер создания/планирования, и понятные статусы участников."

## Входные требования
- Экран `Мои встречи`:
  - вкладки: `Запланированные` (по умолчанию), `История встреч`.
  - в `Запланированные`: будущие + уже идущие в моменте.
  - в `История`: дата/время, название, запись, конспект.
- Кнопки сверху:
  - `Начать встречу` (создание и немедленный старт),
  - `Запланировать встречу` (создание с датой/временем).
- Единая модалка create/edit с полями:
  - название,
  - участники,
  - тип встречи,
  - комната ожидания (default off),
  - дата/время (для schedule/edit).
- Типы встреч:
  - HR-собеседование
  - Встреча с клиентом
  - Командное совещание
  - Инкогнито
  - Обучение
- Для запланированной встречи:
  - запуск,
  - копирование ссылки (для сотрудника / для внешнего),
  - настройка,
  - удаление.
- В активной конференции:
  - фильтры участников: `Все / В звонке / Не в звонке`.

## Что нужно выдать
1. **Product spec** (коротко и структурно):
   - use-cases,
   - user-flow,
   - edge-cases,
   - non-functional requirements.
2. **UX specification**:
   - структура экрана,
   - поведение табов,
   - состояния карточки встречи,
   - состояния модалки.
3. **Технический дизайн**:
   - API-контракты (create/update/list/start/delete),
   - модели данных встречи,
   - схема пресетов и policy-флагов,
   - deep-link и типы invite-link.
4. **Декомпозиция**:
   - Epic -> US -> Tasks (Frontend/Backend/QA/Design).
5. **Оценка в часах**:
   - `Классика (команда)` и `AI-first (ИИ делает, человек контролирует)`,
   - отдельно MVP и Full,
   - разложение по FE/BE/QA/Design.
6. **Acceptance Criteria**:
   - функциональные,
   - UX,
   - безопасность/доступ.
7. **Rollout plan**:
   - feature flag,
   - миграция и обратная совместимость,
   - метрики успеха.

## Ограничения
- Ответ на русском.
- Без воды, с таблицами там, где это помогает.
- Не предлагай AI-фичи как обязательные: AI-first здесь означает ускорение разработки, не изменение функциональности.
- Явно помечай assumptions и зависимости.
