# Prompt для ИИ: ТЗ #8 (задачи + наблюдатели + вкладка «Наблюдаю»)

Ты senior product engineer в проекте `element-web`.

## Цель

Сделать модуль задач, где пользователь может:
1) создавать задачи;
2) назначать исполнителей;
3) назначать наблюдателей;
4) видеть отдельную вкладку `Наблюдаю` с таблицей задач, за которыми он наблюдает.

## Обязательные требования

- Роли задачи: `author`, `assignee`, `watcher`.
- Исполнитель (`assignee`) строго один.
- Во вкладке `Наблюдаю` таблица со столбцами:
  - кому назначено,
  - заголовок,
  - описание,
  - срок выполнения,
  - статус (`выполнено/не выполнено`).
- Группировка и фильтрация по любым доступным полям (MVP: AND-фильтры).
- Права watcher ограничены (просмотр/контроль, без избыточного редактирования).
- Кнопка `Создать задачу` в header раздела `Задачи`.
- Создание задачи из composer-меню сообщения.
- Номер задачи (`T-xxxx`) как ссылка с открытием карточки задачи по deep-link.
- В карточке своей задачи: комментарий (необязательно) + переключение статуса done/not_done.
- В MVP комментарий один: поле `последний комментарий`.
- В форме создания:
  - `Ответственный(е)` и `Наблюдатели` через user picker с чипами (аватар + имя);
  - в DM по умолчанию ответственный = собеседник;
  - в наблюдателях по умолчанию = создатель (с возможностью удалить).
- Доступ по `T-xxxx` ссылке только для: автора, исполнителя, наблюдателей.
- Для пользователя без доступа по `T-xxxx`: редирект в список задач без деталей + микросообщение "Нет доступа к задаче номер T-xxxx".
- Статус могут менять: автор, исполнитель, наблюдатель.
- Если исполнитель удален/деактивирован, задача автоматически переназначается на автора.
- Задача, созданная из composer, автоматически привязывается к текущему чату/комнате.

## Ограничения

- Не делать монолитный рефакторинг.
- Разделить работу по слоям: data model -> API -> UI table -> filters/grouping.
- Сохранять обратную совместимость текущих разделов.

## Формат результата

1. Список измененных файлов.
2. API контракт(ы) и DTO.
3. Что сделано по ролям и правам.
4. Что сделано по вкладке `Наблюдаю`.
5. Что сделано по фильтрам/группировке.
6. QA checklist + риски.

## Дополнение после текущей реализации UI

Уже реализован UI-слой:
- пункт `Задачи` в левом меню между `ВКС` и `Контакты`;
- отдельный экран задач;
- вкладки `Мои`/`Наблюдаю`;
- сводная таблица;
- базовые фильтры и группировка;
- счетчики `Новые` и `Просрочено`.
- кнопка `Создать задачу` в header;
- pop-up создания задачи;
- создание задачи из composer-меню;
- pop-up просмотра/редактирования задачи по клику и по `T-xxxx` ссылке;
- user pickers с чипами для assignees/watchers и автоподстановки.

Следующий шаг для ИИ: не ломая этот UI, подключить реальный backend data-layer (роль наблюдателя, права, серверные фильтры/группы, уведомления).

## Фокус следующей итерации (для ИИ)

1. Убрать локальное хранение задач и перейти на API.
2. Реализовать серверные deep-links задач с открытием карточки из чата.
3. Добавить реальный поиск пользователей (directory API) в pickers.
4. Оставить в MVP только `последний комментарий`, полноценную ленту комментариев вынести в post-MVP.
