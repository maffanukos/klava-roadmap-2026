# Проблема №6: мультиаккаунт и переключение как в Telegram

## Входные решения (согласовано)

- Поддержка: **неограниченное число аккаунтов**.
- Переключение: **с мягкой перезагрузкой UI** (soft reload), не “мгновенный hot swap”.
- Счетчик у неактивных аккаунтов: показывать **и общее непрочитанное, и важные/упоминания**.
- Сессии: **восстанавливать все добавленные аккаунты** после перезапуска.
- Безопасность: **не запрашивать повторно пароль/2FA при обычном переключении**.
- Точка входа: переключатель в **текущем меню профиля**.
- Действия по аккаунту: `аватар+имя+mxid`, `mute`, `logout`, `reorder`.
- Первый целевой релиз: **реальная мультисессия** (не только UI mock).

---

## Цель

Сделать удобный сценарий работы с несколькими аккаунтами в одном клиенте:

- пользователь видит активный и другие аккаунты;
- видит счетчики непрочитанных для неактивных аккаунтов;
- быстро переключается между аккаунтами без повторного логина;
- управляет аккаунтами в одном месте (mute/logout/reorder).

---

## Scope

### S1. Аккаунт-меню

- В user menu добавить секцию “Аккаунты”.
- Показ текущего активного аккаунта.
- Список остальных аккаунтов с краткой карточкой:
  - аватар, display name, mxid;
  - unread badges (total + important/mentions);
  - статус mute (если включен).

### S2. Действия над аккаунтами

- Переключиться на аккаунт.
- Временно отключить уведомления для аккаунта (mute).
- Выйти из конкретного аккаунта (logout per account).
- Изменить порядок аккаунтов (drag/drop или move up/down).

### S3. Состояние и хранение

- Хранить список аккаунтов и их порядок локально.
- Восстанавливать все аккаунты при старте приложения.
- Восстанавливать последний активный аккаунт.

### S4. Агрегация уведомлений

- Для каждого неактивного аккаунта:
  - общий unread count;
  - count важных/упоминаний.
- Обновление счетчиков в фоне без переключения в аккаунт.

### S5. UX переключения

- Soft reload UX:
  - быстрая смена контекста клиента;
  - сохранение состояния интерфейса в пределах текущего аккаунта;
  - предсказуемый fallback при ошибке переключения.

## Инструкции разработчикам (человеческие)

### Задача A (модель)

1. Не привязывать UI напрямую к raw MatrixClient.
2. Вынести слой `AccountRegistry` + `ActiveAccountStore`.
3. Сразу заложить расширение на N аккаунтов, не “зашивать” 2.

### Задача B (переключение)

1. Переключение делать через единый orchestrator.
2. Добавить явные состояния: `idle/switching/failed`.
3. Любая ошибка switch должна иметь fallback и user-visible сообщение.

### Задача C (меню)

1. Держать структуру компактной: активный сверху, остальные ниже.
2. Для каждого действия аккаунта предусмотреть confirm там, где действие разрушительное (logout).
3. Переупорядочивание хранить сразу после изменения.

### Задача D (уведомления)

1. Счетчики считать отдельно от активного UI рендера.
2. Не блокировать интерфейс меню ожиданием счетчиков.
3. При ошибке источника показывать последний валидный snapshot.

### Задача E (безопасность)

1. Проверить, где физически хранятся токены и как очищаются.
2. При logout аккаунта удалять только его данные.
3. Добавить unit-тесты на изоляцию сессий.

## Тест-кейсы для QA

## F1. Базовое переключение

### TC-F1-01 Switch между 2 аккаунтами

- Шаги: добавить 2 аккаунта, переключиться A->B->A.
- ОР: корректный контекст, без повторного логина.

### TC-F1-02 Switch между 5+ аккаунтами

- Шаги: добавить 5 аккаунтов, выполнить серию переключений.
- ОР: порядок корректный, UI стабилен.

## F2. Счетчики неактивных аккаунтов

### TC-F2-01 Total unread

- Шаги: на неактивный аккаунт отправить несколько сообщений.
- ОР: badge total обновился.

### TC-F2-02 Important/mentions

- Шаги: отправить упоминание в неактивный аккаунт.
- ОР: важный счетчик обновился отдельно.

## F3. Действия аккаунта

### TC-F3-01 Mute account

- Шаги: включить mute на одном неактивном аккаунте.
- ОР: уведомления по нему не всплывают/маркируются muted.

### TC-F3-02 Logout single account

- Шаги: выйти из одного аккаунта.
- ОР: удален только выбранный аккаунт, остальные работают.

### TC-F3-03 Reorder accounts

- Шаги: поменять порядок.
- ОР: порядок сохраняется после перезапуска.

## F4. Восстановление сессий

### TC-F4-01 Restart restore all

- Шаги: перезапустить клиент.
- ОР: все аккаунты восстановлены, активный выбран корректно.

## F5. Ошибки и сеть

### TC-F5-01 Switch при потере сети

- Шаги: отключить сеть во время switch.
- ОР: понятная ошибка + fallback, UI не завис.

### TC-F5-02 Протухшая сессия

- Шаги: переключиться на аккаунт с невалидной сессией.
- ОР: корректный путь восстановления/релогина только для этого аккаунта.
